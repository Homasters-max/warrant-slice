# Proposal

## Why

Проекту нужна библиотека ограничения частоты запросов: вызывающий код должен узнавать, можно ли пропустить очередной
запрос по ключу (клиент, пользователь, эндпоинт), не превышая заданную квоту. Пакет `rate_limiter` сейчас пуст — это
первое поведение, которое в нём появляется.

## What Changes

- Новая возможность `rate-limiter`: ограничитель «token bucket» с квотой N запросов на окно W по каждому ключу.
- Решение по запросу — «пропустить» или «отклонить»; ёмкость ключа пополняется со временем со скоростью N/W, не выше N.
- Ключи независимы: исчерпание квоты одного ключа не влияет на другие.
- Время берётся из источника, который передаёт вызывающий, — поведение проверяемо без ожидания реального времени.

> предыдущего (часы пошли назад): считает прошедшее время нулевым, отклоняет вызов ошибкой или делает что-то иное?

## Capabilities

### New Capabilities

- `rate-limiter`: решение «пропустить / отклонить» для запроса по ключу при квоте N запросов на окно W с пополнением
  со временем.

### Modified Capabilities

Нет.

## Impact

- Код: пакет `src/rate_limiter/` (сейчас только docstring), тесты в `tests/`.
- Зависимости: только стандартная библиотека Python 3.11+; новых зависимостей нет.
- Внешние системы, API и данные не затрагиваются.

## Non-goals

- Распределённое ограничение (общее состояние между процессами или узлами), хранение состояния вне памяти процесса.
- Потокобезопасность и асинхронный API: библиотека рассчитана на вызов из одного потока.
- Иные алгоритмы (fixed window, sliding log), стоимость запроса больше одного токена, ожидание освобождения квоты.
- Вытеснение неактивных ключей и ограничение памяти на число ключей.
