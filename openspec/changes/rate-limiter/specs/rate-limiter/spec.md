# Spec Delta

## Purpose

Решает, пропустить или отклонить очередной запрос по ключу по схеме token bucket: по каждому ключу не больше N запросов
подряд, запас пополняется со скоростью N запросов за окно W.

## ADDED Requirements

### Requirement: Не больше N запросов за окно
<!-- id: REQ-RL-001 -->

Ограничитель SHALL создаваться с квотой N и окном W. N SHALL быть целым числом больше нуля (логическое значение целым не
считается); W SHALL быть конечным числом секунд больше нуля (не логическим значением, не NaN, не бесконечностью). Иная
квота или окно SHALL отклоняться при создании исключением `ValueError`.

Для каждого ключа ограничитель SHALL хранить запас от 0 до N; ключ, по которому запросов ещё не было, начинает с полным
запасом N. Запрос по ключу SHALL пропускаться и уменьшать запас ключа на единицу, если запас не меньше единицы, и иначе
SHALL отклоняться, не меняя запас. Отсюда гарантия квоты: без хода времени по одному ключу пропускается не больше N
запросов подряд, а за любой интервал длиной T — не больше N + T·N/W запросов (за одно окно W — не больше 2N, в
установившемся режиме — не больше N за окно в среднем). Строгого «не больше N в любом скользящем окне W» ограничитель
не гарантирует.

Ключ — любое хешируемое значение; ключи, равные по сравнению на равенство (например `1`, `1.0`, `True`), — один ключ.
Нехешируемый ключ SHALL отклоняться исключением `TypeError` без изменения состояния.

Время ограничитель SHALL брать из источника времени, переданного при создании (функция без аргументов, возвращающая
секунды); если источник не передан — из монотонных часов процесса. Исключение источника времени SHALL передаваться
вызывающему без изменения состояния; значение источника, не являющееся конечным числом, SHALL отклонять запрос
исключением `ValueError` без изменения состояния. Поведение при значении источника меньше предыдущего этим требованием не
определено — это `UNK-RL-001`.

Контракт действует при вызовах ограничителя из одного потока.

#### Scenario: Лимит исчерпан
<!-- id: SCN-RL-001 -->
- **WHEN** ограничитель создан с N = 3 и W = 10 с, источник времени всё время возвращает 0, и по ключу `a` поступают 4
  запроса подряд
- **THEN** первые 3 запроса пропущены, 4-й отклонён

#### Scenario: Независимые ключи
<!-- id: SCN-RL-003 -->
- **WHEN** ограничитель создан с N = 2 и W = 10 с, источник времени всё время возвращает 0, по ключу `a` пропущены 2
  запроса и 3-й отклонён, затем поступают 3 запроса по ключу `b`
- **THEN** по ключу `b` первые 2 запроса пропущены, 3-й отклонён, а следующий запрос по ключу `a` по-прежнему отклонён

#### Scenario: Недопустимая конфигурация
<!-- id: SCN-RL-004 -->
- **WHEN** ограничитель создаётся с N, равным 0, -1, 2.5 или `True`, либо с W, равным 0, -1, NaN или бесконечности
- **THEN** создание завершается исключением `ValueError`

### Requirement: Пополнение со временем
<!-- id: REQ-RL-002 -->

Запас ключа SHALL пополняться непрерывно со скоростью N/W в секунду по времени источника, прошедшему с предыдущего
запроса по этому ключу, включая дробные доли, и SHALL не превышать N. Запрос пропускается, когда накопленный запас
достигает единицы; запас меньше единицы запрос не пропускает. Погрешность вычисления запаса SHALL быть не больше 1e-9
единицы: запас, отличающийся от единицы не больше чем на 1e-9, считается достигшим единицы.

#### Scenario: Пополнение
<!-- id: SCN-RL-002 -->
- **WHEN** ограничитель создан с N = 2 и W = 10 с; при времени источника 0 по ключу `a` поступают 3 запроса; при времени
  4 с — 1 запрос; при времени 5 с — 2 запроса; при времени 65 с — 3 запроса
- **THEN** при 0 первые 2 запроса пропущены, 3-й отклонён; при 4 с запрос отклонён (запас 0.8); при 5 с первый запрос
  пропущен, второй отклонён; при 65 с первые 2 запроса пропущены, 3-й отклонён (запас не превысил N)
