# Spec Delta

## Purpose

Решает, пропустить или отклонить очередной запрос по ключу по схеме token bucket: по каждому ключу не больше N запросов
подряд, запас пополняется со скоростью N запросов за окно W.

## ADDED Requirements

### Requirement: Квота N запросов на окно
<!-- id: REQ-RL-001 -->

Библиотека SHALL предоставлять ограничитель, создаваемый вызовом `RateLimiter(limit, window, clock=None)`, где `limit` —
квота N, `window` — окно W в секундах, `clock` — источник времени; решение по запросу SHALL возвращаться вызовом
`allow(key)`: `True` — запрос пропущен, `False` — отклонён.

N SHALL быть значением типа `int` (не `bool`) от 1 до 2^53 включительно. W SHALL быть значением типа `int` или `float`
(не `bool`), больше нуля и представимым конечным числом с плавающей точкой двойной точности. Иная квота или окно SHALL
отклоняться при создании исключением `ValueError`. Источник времени — вызываемый объект без аргументов, возвращающий
секунды; при `clock=None` ограничитель SHALL брать время из монотонных часов процесса; невызываемый источник, отличный от
`None`, SHALL отклоняться при создании исключением `TypeError`. При создании источник времени не вызывается.

Для каждого ключа ограничитель SHALL хранить запас от 0 до N; ключ, по которому запросов ещё не было, начинает с полным
запасом N. Запрос по ключу SHALL пропускаться и уменьшать запас ключа на единицу, если запас больше или равен единице, и
иначе SHALL отклоняться, не уменьшая запас. Отсюда гарантия квоты для источника времени, значения которого не убывают:
без хода времени по одному ключу пропускается не больше N запросов подряд, а за любой интервал времени источника длиной
T — не больше N + T·N/W запросов, с точностью до ошибки округления на дробных значениях (`REQ-RL-002`). Если источник
идёт назад, гарантия не действует (`REQ-RL-002`, `UNK-RL-001`). Строгое «не больше N в любом скользящем окне W»
ограничитель не гарантирует.

Ключ — любое хешируемое значение. Два ключа — один ключ, если это один и тот же объект либо их хеши равны и они равны по
сравнению на равенство (например `1`, `1.0` и `True` — один ключ). Нехешируемый ключ SHALL отклоняться исключением
`TypeError`; исключение, брошенное хешированием или сравнением ключа, SHALL передаваться вызывающему.

При каждом запросе ограничитель SHALL сначала проверить ключ, затем ровно один раз вызвать источник времени. Исключение
источника времени SHALL передаваться вызывающему; значение источника, не являющееся значением типа `int` или `float` (не
`bool`), представимым конечным числом с плавающей точкой двойной точности, SHALL отклонять запрос исключением
`ValueError`. Запрос, завершившийся исключением, SHALL не менять состояние ограничителя, включая запас и отметку времени
ключа.

Контракт действует при вызовах ограничителя из одного потока.

#### Scenario: Лимит исчерпан
<!-- id: SCN-RL-001 -->
- **WHEN** ограничитель создан с N = 3 и W = 10 с, источник времени всё время возвращает 0, и по ключу `a` поступают 4
  запроса подряд
- **THEN** первые 3 запроса пропущены, 4-й отклонён

#### Scenario: Независимые ключи
<!-- id: SCN-RL-003 -->
- **WHEN** ограничитель создан с N = 2 и W = 10 с, источник времени всё время возвращает 0, по ключу `a` пропущены 2
  запроса и 3-й отклонён, затем поступают 3 запроса по ключу `b`
- **THEN** по ключу `b` первые 2 запроса пропущены, 3-й отклонён, а следующий запрос по ключу `a` по-прежнему отклонён

#### Scenario: Недопустимая конфигурация
<!-- id: SCN-RL-004 -->
- **WHEN** ограничитель создаётся с N, равным 0, -1, 2^53 + 1, 3.0 или `True`, либо с W, равным 0, -1, NaN, бесконечности,
  10^400, `True` или строке `"10"`, либо с источником времени, равным числу 5
- **THEN** при недопустимых N или W создание завершается исключением `ValueError`, при источнике-числе — `TypeError`

#### Scenario: Отказы при запросе
<!-- id: SCN-RL-006 -->
- **WHEN** ограничитель создан с N = 2 и W = 10 с и источником времени, который считает свои вызовы и возвращает значение,
  заданное тестом; поступают по очереди: запрос с ключом `[1]` (список); при времени 0 запрос по ключу `a`; запросы по
  ключу `a`, при которых источник возвращает NaN, бросает `RuntimeError` и возвращает 10^400; затем при времени 5 с — 3
  запроса по ключу `a`; затем при времени 5 с — запросы по ключам `1`, `1.0` и `True`
- **THEN** после создания источник не вызывался; запрос с ключом `[1]` завершается `TypeError`, источник при нём не
  вызывается; запрос при времени 0 пропущен; запросы с NaN и 10^400 завершаются `ValueError`, запрос с отказом источника —
  тем же `RuntimeError`; при 5 с первые 2 запроса по `a` пропущены, 3-й отклонён (отказавшие запросы не изменили ни запас,
  ни отметку 0); из запросов по `1`, `1.0` и `True` пропущены первые 2, 3-й отклонён (один ключ); источник вызван ровно
  один раз на каждый запрос, кроме запроса с ключом `[1]`

### Requirement: Пополнение со временем
<!-- id: REQ-RL-002 -->

Запас ключа SHALL пополняться со скоростью N/W в секунду по времени источника, прошедшему с отметки ключа, включая
дробные доли, и SHALL не превышать N. Отметка ключа — значение источника при предыдущем успешно обработанном запросе по
этому ключу (пропущенном или отклонённом). Запрос пропускается, когда запас больше или равен единице при точном
сравнении; запас меньше единицы запрос не пропускает. Запас вычисляется в двоичной арифметике с плавающей точкой
двойной точности: если значения времени, W, N/W-приращения и накопленный запас представимы точно, решение на границе
точное; иначе решение на границе может определяться ошибкой округления.

Если источник времени вернул значение меньше отметки ключа (часы пошли назад), ограничитель SHALL считать прошедшее время
равным нулю — запас не меняется — и SHALL сдвинуть отметку ключа на новое, меньшее значение; решение по запросу
принимается по неизменённому запасу (`UNK-RL-001`). Следствие: после возврата часов вперёд отрезок отката засчитывается
в пополнение повторно, и гарантия квоты `REQ-RL-001` для такого источника не действует.

#### Scenario: Пополнение
<!-- id: SCN-RL-002 -->
- **WHEN** ограничитель создан с N = 2 и W = 8 с; при времени источника 0 по ключу `a` поступают 3 запроса; при времени
  3 с — 1 запрос; при времени 4 с — 2 запроса; при времени 64 с — 3 запроса
- **THEN** при 0 первые 2 запроса пропущены, 3-й отклонён; при 3 с запрос отклонён (запас 0.75); при 4 с первый запрос
  пропущен (запас 1), второй отклонён; при 64 с первые 2 запроса пропущены, 3-й отклонён (запас не превысил N)

#### Scenario: Часы пошли назад
<!-- id: SCN-RL-005 -->
- **WHEN** ограничитель создан с N = 2 и W = 10 с; при времени источника 10 с по ключу `a` поступают 3 запроса; затем
  источник возвращает 5 с и поступает 1 запрос; затем источник возвращает 10 с и поступают 2 запроса
- **THEN** при 10 с первые 2 запроса пропущены, 3-й отклонён; при 5 с запрос отклонён без ошибки; при повторных 10 с
  первый запрос пропущен (запас 1 накоплен от сдвинутой отметки 5 с), второй отклонён
