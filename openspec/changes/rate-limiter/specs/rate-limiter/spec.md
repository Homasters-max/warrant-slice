# Spec Delta

## Purpose

Решает, пропустить или отклонить очередной запрос по ключу по схеме token bucket: по каждому ключу не больше N запросов
подряд, запас пополняется со скоростью N запросов за окно W.

## ADDED Requirements

### Requirement: Квота N запросов на окно
<!-- id: REQ-RL-001 -->

Ограничитель SHALL создаваться с квотой N, окном W и, необязательно, источником времени. N SHALL быть значением типа
`int` (не `bool`) от 1 до 2^53 включительно. W SHALL быть значением типа `int` или `float` (не `bool`), конечным и больше
нуля. Иная квота или окно SHALL отклоняться при создании исключением `ValueError`. Источник времени — вызываемый объект
без аргументов, возвращающий секунды; если источник не передан, ограничитель SHALL брать время из монотонных часов
процесса; переданный невызываемый источник SHALL отклоняться при создании исключением `TypeError`.

Для каждого ключа ограничитель SHALL хранить запас от 0 до N; ключ, по которому запросов ещё не было, начинает с полным
запасом N. Запрос по ключу SHALL пропускаться и уменьшать запас ключа на единицу, если запас больше или равен единице, и
иначе SHALL отклоняться, не уменьшая запас. Отсюда гарантия квоты: без хода времени по одному ключу пропускается не больше
N запросов подряд, а за любой интервал длиной T — не больше N + T·N/W запросов. Строгое «не больше N в любом скользящем
окне W» ограничитель не гарантирует.

Ключ — любое хешируемое значение. Два ключа — один ключ, если это один и тот же объект либо они равны по сравнению на
равенство (например `1`, `1.0` и `True` — один ключ). Нехешируемый ключ SHALL отклоняться исключением `TypeError`.

При каждом запросе ограничитель SHALL сначала проверить ключ, затем ровно один раз вызвать источник времени. Исключение
источника времени SHALL передаваться вызывающему; значение источника, не являющееся конечным числом типа `int` или
`float` (не `bool`), SHALL отклонять запрос исключением `ValueError`. Запрос, завершившийся исключением, SHALL не менять
состояние ограничителя.

Контракт действует при вызовах ограничителя из одного потока.

#### Scenario: Лимит исчерпан
<!-- id: SCN-RL-001 -->
- **WHEN** ограничитель создан с N = 3 и W = 10 с, источник времени всё время возвращает 0, и по ключу `a` поступают 4
  запроса подряд
- **THEN** первые 3 запроса пропущены, 4-й отклонён

#### Scenario: Независимые ключи
<!-- id: SCN-RL-003 -->
- **WHEN** ограничитель создан с N = 2 и W = 10 с, источник времени всё время возвращает 0, по ключу `a` пропущены 2
  запроса и 3-й отклонён, затем поступают 3 запроса по ключу `b`
- **THEN** по ключу `b` первые 2 запроса пропущены, 3-й отклонён, а следующий запрос по ключу `a` по-прежнему отклонён

#### Scenario: Недопустимая конфигурация
<!-- id: SCN-RL-004 -->
- **WHEN** ограничитель создаётся с N, равным 0, -1, 2^53 + 1, 3.0 или `True`, либо с W, равным 0, -1, NaN, бесконечности,
  `True` или строке `"10"`, либо с невызываемым источником времени
- **THEN** при недопустимых N или W создание завершается исключением `ValueError`, при невызываемом источнике —
  `TypeError`

#### Scenario: Отказы при запросе
<!-- id: SCN-RL-006 -->
- **WHEN** ограничитель создан с N = 1 и W = 10 с, источник времени возвращает 0; поступают по очереди: запрос с ключом
  `[1]` (список); запрос по ключу `a`, при котором источник возвращает NaN; запрос по ключу `a`, при котором источник
  бросает `RuntimeError`; затем при времени 0 запросы по ключам `1`, `1.0` и `True`
- **THEN** первый запрос завершается `TypeError`, второй — `ValueError`, третий — тем же `RuntimeError`; из трёх
  последних запросов пропущен только первый (один ключ), а следующий запрос по ключу `a` при времени 0 пропущен
  (отказавшие запросы не израсходовали его запас)

### Requirement: Пополнение со временем
<!-- id: REQ-RL-002 -->

Запас ключа SHALL пополняться со скоростью N/W в секунду по времени источника, прошедшему с отметки ключа, включая
дробные доли, и SHALL не превышать N. Отметка ключа — значение источника при предыдущем запросе по этому ключу
(пропущенном или отклонённом). Запрос пропускается, когда запас больше или равен единице при точном сравнении; запас
меньше единицы запрос не пропускает. Запас вычисляется в двоичной арифметике с плавающей точкой: при целых значениях
времени и W, для которых прошедшее время · N / W представимо точно, решение на границе точное; при дробных значениях
решение на границе может определяться ошибкой округления.

Если источник времени вернул значение меньше отметки ключа (часы пошли назад), ограничитель SHALL считать прошедшее время
равным нулю — запас не меняется — и SHALL сдвинуть отметку ключа на новое, меньшее значение; решение по запросу
принимается по неизменённому запасу (`UNK-RL-001`).

#### Scenario: Пополнение
<!-- id: SCN-RL-002 -->
- **WHEN** ограничитель создан с N = 2 и W = 10 с; при времени источника 0 по ключу `a` поступают 3 запроса; при времени
  4 с — 1 запрос; при времени 5 с — 2 запроса; при времени 65 с — 3 запроса
- **THEN** при 0 первые 2 запроса пропущены, 3-й отклонён; при 4 с запрос отклонён (запас 0.8); при 5 с первый запрос
  пропущен, второй отклонён; при 65 с первые 2 запроса пропущены, 3-й отклонён (запас не превысил N)

#### Scenario: Часы пошли назад
<!-- id: SCN-RL-005 -->
- **WHEN** ограничитель создан с N = 2 и W = 10 с; при времени источника 10 с по ключу `a` поступают 3 запроса; затем
  источник возвращает 5 с и поступает 1 запрос; затем источник возвращает 10 с и поступают 2 запроса
- **THEN** при 10 с первые 2 запроса пропущены, 3-й отклонён; при 5 с запрос отклонён без ошибки; при повторных 10 с
  первый запрос пропущен (запас 1 накоплен от сдвинутой отметки 5 с), второй отклонён
