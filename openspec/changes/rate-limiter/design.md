# Design

## Context

Пакет `src/rate_limiter/` содержит только docstring; тесты запускаются `python -m pytest` (check `tests-passed`).
Мотивация — proposal.md, раздел Why; поведение — `specs/rate-limiter/spec.md` (`REQ-RL-001`, `REQ-RL-002`).

## Goals / Non-Goals

**Goals:**
- Детерминированное поведение в тестах: время только из внедрённого источника, без `sleep` и системных часов.
- Только стандартная библиотека Python 3.11+.

**Non-Goals:**
- Потокобезопасность, распределённое состояние, вытеснение ключей — см. Non-goals в proposal.md.

## Decisions

### D-1. Алгоритм — token bucket с ленивым пополнением

Каждому ключу соответствуют запас `tokens` (float) и отметка `last` (время последнего пересчёта). При запросе:
`elapsed = now - last`, `tokens = min(N, tokens + elapsed * N / W)`, `last = now`; если `tokens >= 1` — пропустить и
`tokens -= 1`, иначе отклонить. Новый ключ создаётся с `tokens = N`, `last = now`. Скорость считается как
`elapsed * N / W`, а не `elapsed * (N / W)`: для целых значений времени это даёт точные границы сценария `SCN-RL-002`
(5 с · 2 / 10 = 1.0).

Отвергнуто:
- Fixed window (счётчик на окно): пропускает до 2N запросов на стыке окон и не даёт непрерывного пополнения
  `REQ-RL-002`.
- Sliding log (метки всех запросов): память O(N) на ключ без выигрыша для требований.
- Фоновый таймер пополнения: требует потоков и реального времени, ломает детерминизм тестов.

### D-2. Внедряемый источник времени

Конструктор принимает `clock: Callable[[], float]` (секунды); по умолчанию `time.monotonic`. Тесты передают фальшивые
часы, продвигаемые вручную.

Отвергнуто:
- `time.time()` напрямую: не монотонно и не управляется из тестов.
- Передача `now` в каждый вызов: переносит ответственность за согласованность времени на вызывающего и расширяет API.

### D-3. API

`RateLimiter(limit: int, window: float, clock=time.monotonic)`; метод `allow(key: Hashable) -> bool`.
`limit <= 0`, нецелый `limit` (в том числе `bool`) или `window <= 0` — `ValueError` в конструкторе (`REQ-RL-001`).
Состояние ключей — `dict` в памяти экземпляра.

Отвергнуто:
- Исключение при отклонении вместо `bool`: отклонение — штатный исход, а не ошибка.

### D-4. Часы, идущие назад — не решено

Поведение при `now < last` зависит от `UNK-RL-001` и не реализуется до решения maintainer'а. Варианты для решения:
(а) считать `elapsed = 0` и сдвинуть `last` на `now`; (б) считать `elapsed = 0`, `last` не менять;
(в) `ValueError` из `allow`. Решение закроет UNKNOWN и, при необходимости, добавит сценарий в spec.

> **UNKNOWN** `UNK-RL-001` · blocking — что делает ограничитель, если источник времени вернул значение меньше
> предыдущего (часы пошли назад)?

## Risks / Trade-offs

- [Память растёт с числом ключей] → вытеснение вне scope (proposal.md, Non-goals); отмечено в docstring.
- [Ошибка округления float при дробном времени] → сравнение `tokens >= 1` на точных границах сценариев; дробное время
  в тестах не используется для граничных проверок.
- [Вызов из нескольких потоков] → вне scope; docstring предупреждает об однопоточном использовании.
