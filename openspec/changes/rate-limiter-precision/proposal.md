# Proposal

## Why

`REQ-RL-001` требует, чтобы окно W и значение источника времени были «представимым конечным числом с плавающей точкой
двойной точности». Формулировка допускает два прочтения для значений типа `int`, которые double не представляет точно
(например 2^53 + 1): «`float(x)` конечен, `int` округляется» или «double представляет x точно». Последний review
Change rate-limiter (находка F-1, `RUN-01M3FVYX2AN1AYX48W047KT7BA`) отметил это как MAJOR: сценарии `SCN-RL-004` и
`SCN-RL-006` проверяют только 10^400, которое отклоняют оба прочтения. Change оставляет в `REQ-RL-001` одно прочтение.

## What Changes

- `REQ-RL-001` (MODIFIED): правило для W и для значения источника времени задано один раз — термином «значение секунд»:
  `int` или `float` (не `bool`), которое конечное число двойной точности представляет точно; иное — `ValueError`.
  Значение `int`, которое double не представляет точно (2^53 + 1), теперь отклоняется, а не округляется.
- Новый сценарий `SCN-RL-007`: 2^53 + 1, 2^53 и 2^53 + 2 для W и для значения источника времени.
- Код и тесты `rate_limiter` приводятся к этому правилу: сейчас код принимает 2^53 + 1 с округлением.

> **UNKNOWN** `UNK-RL-002` · blocking — что значит «представимо конечным числом с плавающей точкой двойной точности»
> для W и значения источника типа `int`, которое double не представляет точно: (A) `float(x)` конечен без
> `OverflowError`, `int` округляется до ближайшего double; (B) double представляет x точно, иначе `ValueError`? Одно
> ли правило для W и для значения источника? **Решено maintainer'ом** (PR #7): вариант B — принимается, только если число
> точно представимо конечным double, иначе `ValueError`; 2^53 + 1 — `ValueError`, 2^53 — принимается; правило для W и для
> часов одно.

`UNK-RL-001` в record этого Change только резервирует номер: он занят решением Change rate-limiter (часы назад) в main
spec `rate-limiter`.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `rate-limiter`: уточнено правило допустимых значений W и источника времени в `REQ-RL-001`.

## Impact

- Spec: `openspec/specs/rate-limiter/spec.md`, `REQ-RL-001`.
- Код: `src/rate_limiter/__init__.py` — проверка значения секунд; тесты в `tests/`.
- Совместимость: окно W и значения часов типа `int`, которые double не представляет точно, раньше принимались с
  округлением, теперь отклоняются `ValueError`. Для `float` и для `int` не больше 2^53 по модулю поведение не меняется.
- Зависимости, внешние системы и данные не затрагиваются.

## Non-goals

- Прочие находки review 4 Change rate-limiter (F-2 — F-8): формулировка Purpose, порядок проверок конструктора, часы
  по умолчанию, повторный вход, переполнение при крайних величинах.
- Изменение границ N, семантики token bucket и поведения при часах, идущих назад (`UNK-RL-001` Change rate-limiter).
